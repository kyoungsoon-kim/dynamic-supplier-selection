## 코드에서 확인한 제약

- 상태와 체크포인트: 비교한 두 v1은 10차원·hidden128·3층·8head다. `serve/model.py`·`app.py`의 v3는 18차원·hidden192·4층이며, 이번 비용 비교 대상이 아니다.
- 모델 토큰: 상태 전체를 `unsqueeze(1)`로 토큰 1개로 만든다. 연속 수량 head에 선택업체 임베딩을 연결하며 연속 행동 집합의 크기가 유한한 K+Q가 됐다고 설명하지 않는다.
- 환경: h=5, b=1000, omega=500, CAP=2000. 수요의 표준편차는 시점별 평균의 20%. 음수 재고는 이월하며 lost-sales가 아니다.
- 시간 순서: 주문을 pipeline[tau]에 넣은 뒤 pipeline[1]을 당일 입고한다. tau=0·1은 모두 당일 수요 전에 도착한다. 의도한 실제 리드타임과 차이가 있으므로 코드 수정 뒤에는 재평가해야 한다.
- 평가: BSP의 S를 선택한 시나리오를 성과 보고에도 쓴다. 현재 공개 trainer의 checkpoint 선택 시드 0~3은 평가 0~7과 겹치지만, v1의 원래 학습·선택 이력 전체가 남아 있지는 않다.
- 통계: 시드당 시작일은 하나다. 256개 경로가 모두 독립적인 계절 표본인 것은 아니다. CPU와 CUDA 난수열이 같다고 가정하지 않는다. CUDA 탐색은 A 결과가 CPU와 달라 전체 비교 전에 중단했고 이번 결과로 인용하지 않는다.
- 종료: 200일 뒤 재고·미입고 주문·백오더를 별도로 정산하지 않는다.
- 학습 설명: REINFORCE는 log_prob × detached advantage로 학습한다. MOQ 아래 행동의 실제 주문량이 같아지는 현상만으로 모든 gradient가 0이라고 할 수 없다. 원인별 ablation은 하지 않았다.
- 계보: 현재 `serve/train.py`는 13차원 v2와 best_model_v2.pt를 사용한다. 초기 설계의 별도 baseline t-test 교체 루프도 현재 코드에는 없다. v1 학습을 현재 파일로 그대로 복구했다고 주장하지 않는다.

## 과거 기록 처리

59%는 초기 A 한 업체 휴리스틱 비교이며 전체 최저비용 대비 성과가 아니다. 6월 POLICY_ANALYSIS·DEPLOYMENT의 C 8.93M·구12.64M·재학습7.57M·15.2%·1.42배·40.1%는 과거 기록으로 보존한다. 당시 평가 코드가 없어 차이의 원인은 특정하지 못했다. 두 역사 문서에는 재사용 금지와 이번 보고서 링크를 추가했다. 모델 재학습·동역학 수정·라이브 재배포는 하지 않았다.
